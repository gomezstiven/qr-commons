# Support

QR Commons is currently pre-alpha and maintained as an independent open-source project.

## Community support

For normal usage questions, implementation problems, or design discussion:

- open a GitHub issue when there is a reproducible bug or concrete project change;
- use discussions when enabled for broader questions or proposals;
- search existing issues before opening duplicates.

Issues may be written in English or Spanish.

## What maintainers can reasonably support

The project aims to provide:

- clear documentation for supported APIs and runtimes;
- reproducible examples;
- actionable error behavior;
- bug fixes for maintained releases once releases exist;
- migration guidance when stable contracts change;
- security handling according to `SECURITY.md`.

## What the project does not currently promise

QR Commons does not currently provide:

- response-time or resolution-time SLAs;
- guaranteed support for unreleased/internal APIs;
- integration support for every framework or platform;
- custom implementation work through the public issue tracker;
- guaranteed backwards compatibility before a contract is declared stable.

## Self-hosting and downstream use

The project is intentionally designed for self-hosting and downstream integration.

Maintainers cannot operate or troubleshoot every downstream environment, but issues are welcome when they reveal a bug or undocumented portability constraint in QR Commons itself.

When reporting an integration problem, provide the smallest reproduction that isolates QR Commons behavior from application-specific code.

## Security

Do not use normal support channels for vulnerabilities that should be disclosed privately. See [SECURITY.md](./SECURITY.md).

## Commercial support

The Apache-2.0 license permits commercial use. The existence of commercial support, consulting, sponsorship, or downstream paid products is separate from the guarantees of the open-source project.

No commercial relationship is required to use the static QR Commons core.
